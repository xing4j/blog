# DDD 领域驱动设计入门：核心概念与实践

<div class="post-meta">📅 2025-11-29 &nbsp;·&nbsp; 🏷️ <span class="tag">DDD</span> <span class="tag">系统设计</span></div>

DDD（Domain-Driven Design）通过以业务领域为核心建模，使代码结构与业务逻辑高度对齐，适合复杂业务系统。

---

## 一、核心概念

```
战略设计（宏观）
  ├── 限界上下文（Bounded Context）  ── 业务域的边界
  ├── 通用语言（Ubiquitous Language） ── 开发与业务的共同语言
  └── 上下文映射（Context Map）       ── 上下文间的协作关系

战术设计（微观）
  ├── 实体（Entity）      ── 有唯一标识，状态可变
  ├── 值对象（Value Object）── 无标识，不可变，通过值判断相等
  ├── 聚合根（Aggregate Root）── 聚合的入口，保证一致性
  ├── 领域服务（Domain Service）── 不属于单个实体的业务逻辑
  ├── 领域事件（Domain Event）── 记录领域内发生的重要事件
  └── 仓储（Repository）── 聚合的持久化抽象
```

## 二、限界上下文示例

```
电商系统按限界上下文划分：

[用户上下文]        [订单上下文]        [商品上下文]
  - 注册/登录         - 下单/支付         - 商品管理
  - User 实体         - Order 聚合根      - Product 实体
                      - OrderItem 实体    - Price 值对象

[库存上下文]        [通知上下文]
  - 库存扣减           - 短信/邮件通知
  - Stock 聚合根       - 消费领域事件

各上下文通过领域事件（异步）或 ACL（防腐层）协作
```

## 三、实体 vs 值对象

```java
// 实体：有唯一标识（id），可变
@Entity
public class Order {
    @Id
    private OrderId id;  // 强类型 ID（值对象）
    private UserId userId;
    private OrderStatus status;
    private List<OrderItem> items;
    private Money totalAmount;  // 值对象
    
    // 行为方法（充血模型）
    public void pay() {
        if (status != OrderStatus.PENDING) {
            throw new DomainException("只有待支付订单才能支付");
        }
        this.status = OrderStatus.PAID;
        // 发布领域事件
        DomainEvents.publish(new OrderPaidEvent(this.id));
    }
}

// 值对象：无标识，不可变，equals 比较值
@Embeddable
public final class Money {
    private final BigDecimal amount;
    private final String currency;

    public Money(BigDecimal amount, String currency) {
        Assert.isTrue(amount.compareTo(BigDecimal.ZERO) >= 0, "金额不能为负");
        this.amount = amount;
        this.currency = currency;
    }

    public Money add(Money other) {
        Assert.isTrue(currency.equals(other.currency), "币种必须相同");
        return new Money(amount.add(other.amount), currency);  // 返回新对象
    }

    @Override
    public boolean equals(Object o) {
        if (!(o instanceof Money m)) return false;
        return amount.compareTo(m.amount) == 0 && currency.equals(m.currency);
    }
}
```

## 四、聚合设计原则

```java
// 聚合根：Order（维护一致性边界）
// 规则：只能通过 Order 操作 OrderItem，不能直接操作 OrderItem

@Entity
public class Order {  // 聚合根
    @OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    // 通过聚合根添加商品（保护不变量）
    public void addItem(ProductId productId, int quantity, Money price) {
        if (status != OrderStatus.DRAFT) {
            throw new DomainException("已提交的订单不能修改");
        }
        items.stream()
            .filter(item -> item.getProductId().equals(productId))
            .findFirst()
            .ifPresentOrElse(
                item -> item.increaseQuantity(quantity),
                () -> items.add(new OrderItem(productId, quantity, price))
            );
        recalculateTotal();  // 维护聚合内一致性
    }
}
```

## 五、仓储模式

```java
// 仓储接口定义在领域层
public interface OrderRepository {
    Order findById(OrderId id);
    void save(Order order);
    List<Order> findByUserId(UserId userId, OrderStatus status);
}

// 仓储实现在基础设施层（Infrastructure）
@Repository
public class OrderRepositoryImpl implements OrderRepository {
    @Autowired
    private OrderJpaRepository jpaRepo;
    @Autowired
    private OrderConverter converter;  // 领域对象 <-> 数据库对象转换

    @Override
    public Order findById(OrderId id) {
        return jpaRepo.findById(id.getValue())
            .map(converter::toDomain)
            .orElseThrow(() -> new OrderNotFoundException(id));
    }
    
    @Override
    public void save(Order order) {
        jpaRepo.save(converter.toPo(order));
    }
}
```


## 总结

| DDD 概念 | 传统 MVC 对应 | 核心价值 |
|---------|-------------|---------|
| 聚合根 | Service + 多个 Entity | 保证业务一致性 |
| 值对象 | 普通字段 | 明确业务语义（金额、地址）|
| 领域服务 | Service 层 | 跨实体的业务逻辑 |
| 仓储 | Mapper/DAO | 解耦领域与持久化 |
| 领域事件 | 直接调用 | 解耦上下文协作 |

DDD 适合**复杂业务系统**（微服务拆分依据），CRUD 项目无需过度引入。
