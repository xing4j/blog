# ELK Stack 日志采集与分析

<div class="post-meta">📅 2026-03-11 &nbsp;·&nbsp; 🏷️ <span class="tag">ELK</span> <span class="tag">DevOps</span></div>

ELK（Elasticsearch + Logstash + Kibana）是最成熟的日志管理方案，现代项目通常用 Filebeat 替代 Logstash 作为轻量采集器。

---

## 一、架构演进

```
经典 ELK：
应用 → Logstash（采集+处理）→ Elasticsearch（存储）→ Kibana（展示）

现代 EFK：
应用 → Filebeat（轻量采集）→ Kafka（缓冲）→ Logstash（处理）→ ES → Kibana

K8s 环境：
DaemonSet Filebeat（每个节点）→ Elasticsearch → Kibana
```

## 二、Spring Boot 日志配置

### JSON 格式输出（便于 ES 解析）

```xml
<!-- pom.xml -->
<dependency>
  <groupId>net.logstash.logback</groupId>
  <artifactId>logstash-logback-encoder</artifactId>
  <version>7.4</version>
</dependency>
```

```xml
<!-- logback-spring.xml -->
<configuration>
  <springProperty scope="context" name="appName" source="spring.application.name"/>

  <appender name="JSON_CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder class="net.logstash.logback.encoder.LogstashEncoder">
      <customFields>{"app":"${appName}"}</customFields>
    </encoder>
  </appender>

  <appender name="JSON_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>/logs/${appName}.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
      <fileNamePattern>/logs/${appName}.%d{yyyy-MM-dd}.log</fileNamePattern>
      <maxHistory>7</maxHistory>
    </rollingPolicy>
    <encoder class="net.logstash.logback.encoder.LogstashEncoder">
      <customFields>{"app":"${appName}"}</customFields>
    </encoder>
  </appender>

  <root level="INFO">
    <appender-ref ref="JSON_CONSOLE"/>
    <appender-ref ref="JSON_FILE"/>
  </root>
</configuration>
```

日志输出示例：
```json
{
  "@timestamp": "2026-03-11T10:30:45.123Z",
  "level": "ERROR",
  "logger": "com.example.OrderService",
  "message": "订单处理失败",
  "app": "order-service",
  "traceId": "abc123",
  "orderId": "ORD-2026051601"
}
```

## 三、Filebeat 配置

```yaml
# filebeat.yml
filebeat.inputs:
  - type: log
    enabled: true
    paths:
      - /logs/*.log
    json.keys_under_root: true   # JSON 字段提升到顶层
    json.message_key: message
    multiline.pattern: '^\d{4}-\d{2}-\d{2}'  # 多行日志合并
    multiline.negate: true
    multiline.match: after

# 直接发送到 Elasticsearch
output.elasticsearch:
  hosts: ["elasticsearch:9200"]
  index: "app-logs-%{+yyyy.MM.dd}"
  username: "${ES_USERNAME}"
  password: "${ES_PASSWORD}"

# 或发送到 Logstash
output.logstash:
  hosts: ["logstash:5044"]

processors:
  - add_host_metadata: ~
  - add_docker_metadata: ~    # K8s 环境自动添加容器/Pod 元数据
```

## 四、Logstash Pipeline

```ruby
# logstash/pipeline/app.conf
input {
  beats {
    port => 5044
  }
}

filter {
  # 解析 traceId 用于链路追踪关联
  if [traceId] {
    mutate {
      add_field => { "[@metadata][trace_id]" => "%{traceId}" }
    }
  }

  # 过滤健康检查日志
  if [request_uri] =~ "/actuator/health" {
    drop {}
  }

  # 将 level 转为大写
  mutate {
    uppercase => ["level"]
  }
}

output {
  elasticsearch {
    hosts => ["elasticsearch:9200"]
    index => "app-logs-%{+YYYY.MM.dd}"
    user => "${ES_USER}"
    password => "${ES_PASSWORD}"
  }
}
```

## 五、Elasticsearch 索引模板

```json
PUT _index_template/app-logs
{
  "index_patterns": ["app-logs-*"],
  "template": {
    "settings": {
      "number_of_shards": 3,
      "number_of_replicas": 1,
      "index.lifecycle.name": "logs-policy"
    },
    "mappings": {
      "properties": {
        "@timestamp": { "type": "date" },
        "level": { "type": "keyword" },
        "app": { "type": "keyword" },
        "message": { "type": "text" },
        "traceId": { "type": "keyword" },
        "userId": { "type": "keyword" }
      }
    }
  }
}
```

## 六、Kibana 常用查询（KQL）

```
# 查询 ERROR 级别日志
level: "ERROR"

# 查询特定服务的错误
app: "order-service" AND level: "ERROR"

# 查询包含关键字的日志
message: "OutOfMemoryError"

# 时间范围 + 特定 traceId
traceId: "abc123def456"

# 按应用统计每分钟错误数（用于创建可视化图表）
# → Aggregation: Date Histogram，Split: app.keyword
```

## 总结

| 组件 | 职责 |
|------|------|
| Filebeat | 轻量日志采集，支持多种输入源 |
| Logstash | 日志清洗、转换、过滤 |
| Elasticsearch | 分布式存储与全文检索 |
| Kibana | 日志查询、可视化、告警 |
| ILM | 自动管理索引生命周期（热/温/冷/删）|
